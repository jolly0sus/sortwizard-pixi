# Sort Wizard — PixiJS

A PixiJS v8 rebuild of the "Sort Wizard" playable ad, reproduced from the
original at `playbox.play.plbx.ai/sortwizard/c1`.

> **Assets.** The artwork, audio and fonts under `public/assets/` are taken
> from the original playable and belong to its authors. They are included here
> only so the reconstruction runs; no licence to them is granted by this
> repository. The code is mine, the art is not.

## Running it

```bash
npm install
npm run dev      # vite dev server
npm run build    # lint + production build into dist/
npm run lint
```

## How the game works

Tap a pipe to drop a box of balls. The box holds 9; the `x3` bar triples them,
so one tap puts **27 balls** on a belt with exactly **27 slots** — one tap is
one beltful.

The board is built in **waves**. The front of the four columns always shows
exactly **9 trays of a single colour**, which is precisely what one tap fills
(9 trays x 3 balls = 27). Clear the wave and the next colour is exposed
underneath. Twelve waves, 108 trays, twelve boxes — no spares.

That gives the run a **single correct line**. Nothing ever leaves the belt, so
a tap of the wrong colour puts 27 balls on the loop that no tray will ever
accept; the belt is full for good and the run is over. Wrong taps are
deliberately *allowed* — blocking them would remove the only way to lose.

### Where the numbers live

Everything is driven from [`src/config.js`](src/config.js):

| | |
| --- | --- |
| balls per box | 9, tripled to 27 |
| belt slots | 27 |
| trays | 108 = 12 waves x 9 |
| columns x rows | 4 x 27 |
| open trays | top one per column |
| boxes | 12 (4 per pipe, one colour each) |

The wave layout is generated by
[`src/entities/trayLayout.js`](src/entities/trayLayout.js), which asserts that
the wave count divides evenly by both the column count and the colour count —
change a number carelessly and the build fails loudly instead of quietly
producing an unplayable board.

## Scene editor

Press **E** in the browser (or load with `?edit=1`) to select objects and
adjust their size and position live. Changes are stored in `localStorage` and
can be exported as a minimal diff against the defaults.
